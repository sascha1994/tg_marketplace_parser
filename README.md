# Telegram Marketplace Parser

Парсер получает товарные предложения из Telegram, проверяет карточки Ozon и Wildberries и публикует подходящие товары в целевой канал.

## Выпуск версии

Вносите изменения через pull request в `main`. В PR обновите `__version__` и добавьте при необходимости заметки о миграции и откате в `releases/vX.Y.Z.md`. CI проверяет код с помощью Ruff, mypy и unittest на Python 3.12.

После успешных проверок и слияния создайте новый тег на проверенном коммите в `main` и отправьте тег в GitHub. Для версии 1.0.12 команды выглядят так:

```bash
git fetch origin main
git tag v1.0.12 origin/main
git push origin refs/tags/v1.0.12
```

Workflow сверит номер тега с кодом, соберёт образ, проверит импорт приложения и загрузку локальной страницы Chromium внутри контейнера. После проверки он отправит этот образ в GHCR с тегами версии и коммита. В GitHub Release будут указаны digest и изменения. После публикации тег образа `stable` получает digest старшей выпущенной версии. Dockhand может установить её вручную по кнопке Update. Для исправлений выпускайте новый номер версии.

## Установка и откат

Сервер загружает готовый образ. Для установки через Dockhand и возврата к предыдущему образу следуйте [инструкции](DOCKHAND_DEPLOYMENT.md). В Compose требуется явно задать `PARSER_IMAGE_TAG` в окружении стека или в `.env` рядом с Compose-файлом. Сохраните конфигурацию приложения и постоянный каталог `PARSER_DATA_DIR` между обновлениями.

### Права на каталог данных (начиная с 1.0.4)

Контейнер запускается от непривилегированного пользователя `app` (`uid=1000`). Перед обновлением выдайте ему права на каталог данных, иначе приложение не сможет писать сессии и базу:

```bash
sudo chown -R 1000:1000 /opt/tg_parser/data
```

Статус работоспособности смотрите в `docker compose ps` (должно быть `healthy`): контейнер считается здоровым, пока файл `data/heartbeat` обновлялся менее 5 минут назад. Логи Docker ротируются (5 файлов по 10 МБ).

### Первый запуск и перенос существующего сервера

Перед первым запуском подготовьте `.env` приложения и каталог данных. При переносе с существующего сервера остановите старый контейнер и задайте `PARSER_DATA_DIR` равным пути к прежнему каталогу данных. Не удаляйте базу, сессии и другие данные приложения; перед обновлением сделайте резервную копию.
