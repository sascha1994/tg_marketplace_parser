# Обновление через Dockhand

Репозиторий автоматически собирает и публикует готовые Docker-образы в GitHub Container Registry (GHCR):

- **Ветка `releases` (готовые релизы):**
  - При каждом `push` или merge в `releases` (а также при `push` тега `vX.Y.Z`) запускаются тесты, затем публикуются образы **`:stable`**, **`:latest`**, **`:X.Y.Z`** и **`:sha-<commit>`**, а на GitHub автоматически создаётся релиз `vX.Y.Z`.
  - Dockhand сравнивает локальный digest образа с новым digest тега `:stable` (или `:latest`) в GHCR — поэтому при нажатии **Проверить обновления / Обновить** (или по расписанию) обновление находится и применяется автоматически.
- **Ветка `dev` (версии в разработке):**
  - При каждом `push` в `dev` запускаются тесты и публикуется тестовый образ **`:dev`** (и `:dev-sha-<commit>`).

## 1. Настройка основного стека (релизы) в Dockhand

1. Используйте `docker-compose.yml` из репозитория (в нём уже указан `ghcr.io/sascha1994/tg_marketplace_parser:${PARSER_IMAGE_TAG:-stable}` и `pull_policy: always`).
2. В переменных окружения стека задайте `.env` приложения. По умолчанию используется канал релизов:
   ```env
   PARSER_IMAGE_TAG=stable
   ```
3. Убедитесь, что каталог `/app/data` принадлежит `1000:1000` (`sudo chown -R 1000:1000 /opt/tg_parser/data`) и сохраняется между обновлениями.
4. Для **автоматического обновления** включите расписание в Dockhand:
   - либо глобально: **Settings → Environments → Updates** (задайте расписание проверки/обновления, например каждые 15 минут или раз в час);
   - либо для конкретного контейнера: **Containers → `tg_deals_parser` → Edit → Auto-update**.
5. Для **ручного обновления** после выхода релиза нажмите **Check for Updates** / **Update** — Dockhand найдёт новый digest `:stable`, скачает образ и пересоздаст контейнер.

## 2. Как обновиться до версии в разработке (`dev`)

Есть два удобных способа:

### Способ А — переключить текущий стек на `dev`
1. В настройках стека в Dockhand измените переменную окружения:
   ```env
   PARSER_IMAGE_TAG=dev
   ```
2. Нажмите **Redeploy** (или **Update**).
3. Далее кнопка **Check for Updates / Обновить** будет автоматически находить каждую новую тестовую сборку из ветки `dev`.
4. Чтобы вернуться на стабильный релиз, верните `PARSER_IMAGE_TAG=stable` (или удалите переменную) и нажмите **Redeploy**.

### Способ Б — отдельный тестовый стек (параллельно с продом)
1. Создайте в Dockhand второй стек на базе `docker-compose.dev.yml` (использует образ `:dev`, контейнер `tg_deals_parser_dev` и отдельный каталог данных `./data-dev`).
2. Задайте тестовый `.env` и включите проверку обновлений — оба контура будут обновляться независимо.

## 3. Откат или фиксация конкретной версии

1. Укажите в переменной окружения конкретный тег, например `PARSER_IMAGE_TAG=1.1.5` или `PARSER_IMAGE_TAG=sha-<commit>`.
2. Нажмите **Redeploy**.
3. Чтобы снова получать обновления автоматически, верните `PARSER_IMAGE_TAG=stable` (или `dev`).
