# Установка версии через Dockhand

1. Откройте GitHub Release и проверьте номер версии и digest опубликованного образа. Запишите версию и digest работающего контейнера для отката.
2. В настройках стека отключите автоматическую установку обновлений и автоматический webhook. Старые релизные ветки содержат прежний workflow. При переходе со старой схемы отключите также старый webhook самого стека.
3. Заранее загрузите образ нужной версии. Перед обновлением остановите контейнер и сделайте резервную копию всего каталога, смонтированного в `/app/data`, включая SQLite и Telegram-сессии.
4. В окружении Compose для стека задайте `PARSER_IMAGE_TAG=stable` для обновлений по кнопке. Проверьте прежний путь `PARSER_DATA_DIR`, затем выполните Pull / Redeploy. В стеке должен работать один экземпляр парсера.
5. Дождитесь статуса healthy, сверьте версию в Telegram-админке и обработайте один товар в тестовом канале. Проверьте цену, изображение и запись результата.

В **Settings → Environments → ваше окружение → Updates** включите периодическую проверку образов и оставьте **Automatically update containers** выключенным. Отключите также индивидуальное расписание автоустановки у контейнера. После выхода релиза откройте **Containers → Check for updates** и нажмите стрелку Update у `tg_deals_parser`. Dockhand загрузит новый образ и пересоздаст контейнер с прежним каталогом данных.

При ручном управлении из каталога стека после выбора версии в .env:

```bash
docker compose pull
docker compose up -d --wait --wait-timeout 300
docker compose ps
```

Для отката выберите ранее записанную версию и повторите развёртывание. Проверьте совместимость SQLite по заметкам релиза. Восстановление резервной копии возвращает очередь и историю публикаций к состоянию на момент копирования.
